# 공개 포트폴리오 문구와 구성

적용일: 2026-11-08.

첫 화면은 이름과 `PORTFOLIO`로 소개합니다. 특정 직군으로 자신을 정의하는 직함은 표시하지 않습니다. Backend·REST API, DB 모델링·연동, 알고리즘 구현, 업무 흐름 설계를 실제 수행 작업으로 설명하고, 개별 프로젝트의 구체적인 기술·역할은 유지합니다.

공개 포트폴리오는 지원자가 만든 기능·코드·모델·설계와 그 판단 과정을 설명합니다. 자료 확보 상태를 해명하거나 진위 확인을 요청하는 문장을 작업 소개에 붙이지 않습니다.

## 이번 변경

- 홈 첫 화면에 실제 작업인 SQL 데이터 연결, AI 리포트 Backend와 Python 경로 탐색을 소개했습니다.
- 네 프로젝트의 역할·요약·결과와 24개 섹션의 제목·소개를 작업 중심으로 정리했습니다.
- 수행 작업은 결과를 먼저 보여주고 문제·판단·구현을 이어서 배치했습니다. RentalTrack은 실제 구현한 기능과 팀에서 수행한 협업 경험을 구분합니다.
- 작업별 코드·설계 링크는 설명 아래에 배치했습니다. 전체 자료 목록에서도 내부 증빙 ID 대신 파일의 용도를 표시합니다.
- 출처 등급, ‘검증·추가 설명’, ‘담당 범위·자료 출처’와 반복적인 재구성 안내는 공개 화면에서 제거했습니다. 도식의 캡션은 키 관계·처리 분기·설계 의도를 설명합니다.
- RentalTrack은 제공 ERD 기반의 후속 구현을 반영합니다. 원래 팀 프로젝트 기간과 2026-11의 개편을 나눠 표시하고, 계약 A/B/C 가상 사례 대신 실제 구현한 기록 차수·검수 기준 고정 원리를 설명합니다.
- 데이터 규모·설정값·비교 문제 수의 단위와 의미는 유지합니다. 점포 데이터는 상권·업종별 집계 행으로 설명합니다.

## 문구 작성 기준

‘무엇을 작성·구현·설계했는가’를 첫 항목에 씁니다. 이어서 해결할 문제, 실제 선택한 방식과 처리 동작을 개조식으로 나눕니다. ‘구조를 마련했다’, ‘흐름을 구성했다’처럼 결과물을 알아보기 어려운 표현은 구체적인 산출물로 바꿉니다.

홈 소개·프로젝트 요약·25개 수행 작업은 짧은 명사형 항목으로 작성합니다. JSON 문자열의 줄바꿈 하나를 목록 항목 하나로 렌더링하며, 마침표로 문장을 자동 분리하지 않습니다. `cursor.description` 같은 식별자, SQL 조건, 수식·상태값은 같은 항목 안에 보존합니다. 도식 캡션과 섹션 소개도 짧은 구문으로 정리합니다.

자료 상태·출처·개인 작성 범위의 검토 기록은 기존 JSON 메타데이터와 [추가 자료 목록](portfolio-evidence-needed.md), [소스 대조 기록](portfolio-source-review.md)에서 관리합니다. 원본 링크·고정 커밋·파일 해시와 수치·담당 작업은 이 편집으로 확대하지 않습니다.

## 공개 화면과 작업 기록의 구분

공개 화면의 독자는 채용 담당자와 개발자입니다. 대화에서 요청받은 순서, 파일 확보·복구 경위, 브랜치 정리, 개편 작업 상황을 프로젝트 소개로 옮기지 않습니다. 작업 기록은 `docs/`에 남기고, 공개 본문은 해결한 문제·기술적 판단·구현 동작·결과로 편집합니다. 원본 파일명이나 언어별 구현 유무를 해명하는 문장도 구현 소개에 붙이지 않습니다.

기능 확장·추가 검증의 실제 시점은 프로젝트 기간에 짧게 표시합니다. 경로 최적화 비교는 슬라이드에 미배정 변화·최종 배정·초기해와 탐색 후 비용을 요약하고, 상세 집계 수치는 관련 링크로 제공합니다. 소규모 2입력·입력별 5개 시드라는 적용 범위와 추가 비용 개선이 없다는 결과는 유지합니다. 공개 문구를 간결하게 만들기 위해 이후 작업을 당시 성과로 소급하지 않습니다.

## 반응형 슬라이드

기본 진입 화면은 슬라이드입니다. 기존 `/deck`과 `/projects/:slug?section=...` 주소도 해당 슬라이드로 연결합니다. 데스크톱은 두 작업 카드와 도식을 한 장에 배치하고, 900px 이하에서는 소개·작업 카드·도식을 같은 데이터의 세부 화면으로 나눕니다. 좌우 버튼·키보드·스와이프로 이동하고, 현재 슬라이드와 세부 화면 번호를 함께 표시합니다. 짧은 화면에서 넘치는 내용은 현재 화면 안에서 읽을 수 있도록 하며, 페이지 전체가 긴 스크롤 문서가 되지 않게 합니다.

HTML 다운로드에도 같은 모바일 화면 분할·이동 동작을 적용합니다. 인쇄할 때는 화면 분할을 해제하고 기존 가로 슬라이드 전체를 출력합니다. Contact에는 연락처와 프로젝트 이동 버튼만 표시합니다.
