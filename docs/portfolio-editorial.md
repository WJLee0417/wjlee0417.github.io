# 공개 포트폴리오 문구와 구성

적용일: 2026-11-07.

공개 포트폴리오는 지원자가 만든 기능·코드·모델·설계와 그 판단 과정을 설명합니다. 자료 확보 상태를 해명하거나 진위 확인을 요청하는 문장을 작업 소개에 붙이지 않습니다.

## 이번 변경

- 홈 첫 화면에 실제 작업인 SQL 데이터 연결, AI 리포트 Backend와 Python 경로 탐색을 소개했습니다.
- 네 프로젝트의 역할·요약·결과와 24개 섹션의 제목·소개를 작업 중심으로 정리했습니다.
- 수행 작업은 결과를 먼저 보여주고 문제·판단·구현을 이어서 배치했습니다. RentalTrack의 작업은 설계로 표시합니다.
- 작업별 코드·설계 링크는 설명 아래에 배치했습니다. 전체 자료 목록에서도 내부 증빙 ID 대신 파일의 용도를 표시합니다.
- 출처 등급, ‘검증·추가 설명’, ‘담당 범위·자료 출처’와 반복적인 재구성 안내는 공개 화면에서 제거했습니다. 도식의 캡션은 키 관계·처리 분기·설계 의도를 설명합니다.
- RentalTrack은 프로젝트 유형에 ‘개념 설계’를 명시하고, 계약 A/B/C는 가정한 예시로 표시합니다. 구현 경험과 설계 결과를 서로 바꾸지 않습니다.
- 데이터 규모·설정값·비교 문제 수의 단위와 의미는 유지합니다. 점포 데이터는 상권·업종별 집계 행으로 설명합니다.

## 문구 작성 기준

‘무엇을 작성·구현·설계했는가’를 첫 항목에 씁니다. 이어서 해결할 문제, 실제 선택한 방식과 처리 동작을 개조식으로 나눕니다. ‘구조를 마련했다’, ‘흐름을 구성했다’처럼 결과물을 알아보기 어려운 표현은 구체적인 산출물로 바꿉니다.

홈 소개·프로젝트 요약·25개 수행 작업은 짧은 명사형 항목으로 작성합니다. JSON 문자열의 줄바꿈 하나를 목록 항목 하나로 렌더링하며, 마침표로 문장을 자동 분리하지 않습니다. `cursor.description` 같은 식별자, SQL 조건, 수식·상태값은 같은 항목 안에 보존합니다. 도식 캡션과 섹션 소개도 짧은 구문으로 정리합니다.

자료 상태·출처·개인 작성 범위의 검토 기록은 기존 JSON 메타데이터와 [추가 자료 목록](portfolio-evidence-needed.md), [소스 대조 기록](portfolio-source-review.md)에서 관리합니다. 원본 링크·고정 커밋·파일 해시와 수치·담당 작업은 이 편집으로 확대하지 않습니다.
