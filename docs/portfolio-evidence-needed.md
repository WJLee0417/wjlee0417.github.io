# 포트폴리오 수정 내역과 추가 자료 목록

검토·반영일: 2026-11-07. 현재 프로젝트에 있는 자료만 사용했습니다. 아래의 미확인 사항은 구현 결함 판정이 아니라, 공개 포트폴리오에서 아직 검증할 수 없는 범위입니다.

추가 반영: 사용자가 제공한 공개 저장소에서 코드·문서 12개 항목을 확보하고 재구성 설계 5개 항목과 함께 증빙 브랜치에 연결했습니다. [연결된 자료와 갱신 방법](evidence-workflow.md)을 참고하세요. 아래 목록의 테스트 실행 결과·개인 작성 범위·Excel·당시 보고서 등은 후속 확인 대상입니다.

코드·SQL의 집계식, 품질 상태, 응답 처리 분기, 해시 조회 조건과 PK·FK·JOIN을 대조해 기존 작업 11개의 본문을 보강했습니다. [작업별 근거 기록](portfolio-source-review.md)에 반영 범위와 처리 경계를 정리했습니다.

공개 화면은 이후 [작업 중심 구성](portfolio-editorial.md)으로 개편했습니다. 아래 자료 확보 상태는 내부 후속 작업용이며, 작업별 검증 상태·출처 등급·미확보 안내를 공개 포트폴리오에 표시하지 않습니다.

## 우선 반영한 사항

1. **작업과 코드 연결:** 기능·판단·결과를 먼저 소개하고, 관련 코드·SQL·설계 링크를 작업 설명 아래에 제공합니다.
2. **검증 범위 복원:** P002의 소규모 2문제·대규모 2문제와 P001의 점포 행 수 주의 문구를 유지합니다. 9개 수치 기록의 기존 값은 변경하지 않습니다. P003의 8건·10건·5개는 설정·구조 수치로 구분합니다.
3. **작업 종류 구분:** 개인 담당 작업을 서술하고 RentalTrack은 개념 설계로 소개합니다. 자료 확보·실행·작성 범위의 후속 확인 항목은 이 문서에서 관리합니다.
4. **설명 도식 개선:** 반복 설명만 있던 단계 선택을 정적 목록으로 정리하고, P003의 재사용·신규 생성 분기를 기존 자료에 따라 구분합니다. P004는 기존 설명에 있는 엔터티 관계만 구조화합니다. Member 연결과 미확인 키·카디널리티는 추정하지 않습니다.
5. **자료 접근 경로:** 수행 작업과 탐색 패널에서 관련 코드·설계 파일을 열 수 있습니다. 탐색 패널도 결과·판단·구현을 중심으로 구성합니다.

## 자료 제공 우선순위

### 1순위 — P003 AI 러닝 리포트의 실행 결과와 선택 배경

가장 먼저 필요한 최소 묶음은 **대표 기능의 코드 위치 + 입력·출력 예시 + 테스트 실행 결과**입니다. 프로젝트 전체를 공개할 필요는 없습니다.

- [x] 공개 가능한 저장소 URL과 고정 커밋 및 코드 사본. 대응 자료: E014~E020, E022.
- [x] Fallback·Snapshot 재사용을 확인할 핵심 코드: `AiRunningReportGenerationService.java`, `AiRunningReportStorageService.java`, 관련 매퍼.
- [ ] 정상·누락 데이터·Timeout·Invalid JSON·Provider 비활성 사례의 입력, 예상 결과, 실제 결과. 식별 정보와 API 키는 제거해 주세요.
- [ ] 테스트 실행 명령, 실행 환경, 성공·실패 결과, 실행 시점. 대응 자료: E021.
- [ ] 본인이 작성·수정한 코드와 테스트 범위. 팀원이 작성한 부분은 별도로 구분해 주세요.
- [ ] 실제 Provider를 켜고 외부 호출을 실행했는지, 실행했다면 확인 가능한 기록. 구조 구현·모의 테스트·실제 연동 실행을 구분해 주세요.

설명을 깊게 만들 후속 자료:

- [x] 코드의 평균 페이스·구간 비교 공식, 심박·케이던스 null·표본 수 처리 규칙. 본문에 반영했습니다.
- [x] Snapshot은 집계 DTO의 JSON 직렬화 결과를 SHA-256으로 해시하며, 회원·유형·완료 상태로 조회합니다. Fallback 재사용과 forceRefresh 우회도 확인했습니다.
- [ ] 기본 8건·상한 10건·추세 ±3%를 정한 실제 배경과 작은 입력의 기대값·실제 계산 결과.
- [ ] 모델·프롬프트 버전 변경 시 갱신 정책과 동시 요청 검증 결과. 현재 SQL에는 버전 조건이 없으므로 자동 무효화를 성과로 쓰지 않습니다.
- [x] StorageService의 저장 트랜잭션·필수값 검사와 세션 회원 기준 API 조회 구조를 확인했습니다.
- [ ] 저장 실패·조회 권한·HTTP 오류 응답의 실행 예시와 실제 개인 작성 범위. 구조 확인과 실행 검증을 구분해 주세요.

### 2순위 — P001 상권 데이터의 규모·매핑·조회 근거

최소 묶음은 **매핑 표 발췌 + DDL·JOIN 쿼리 + 행 수 집계 기준**입니다.

- [ ] 원천 데이터의 정확한 이름·제공 기관·URL·기준 시점과 컬럼 설명.
- [ ] 1,650·76,088·9,375행이 각각 원천·정제·적재 중 어느 단계인지, 행의 단위와 집계 쿼리·보고서 발췌. 동일 점포가 여러 행에 나타나는 기준도 필요합니다. 대응 자료: E002, E007.
- [ ] Excel 업종 대응표의 공개 가능한 일부. 대표적인 매핑, 모호한 업종, 미매핑 사례와 처리 기준. 대응 자료: E001.
- [x] 7개 테이블의 DDL, PK·FK·점포의 복합키와 관계. 대응 자료: E003, E004.
- [x] 브랜드 업종코드로 점포·상권을 연결하는 SQL과 Python 조회 결과의 DataFrame 변환. 대응 자료: E005, E006.
- [ ] 해당 SQL의 실제 입력·출력 예시와 중복 후보·미매핑·참조 무결성·JOIN 전후 행 수 검사 결과.
- [ ] 개인 담당 범위를 확인할 보고서·커밋·분담 기록. 본인이 하지 않은 추천 점수 계산과 지도 시각화는 개인 성과에 포함하지 않습니다.

### 3순위 — P002 경로 최적화의 문제 정의와 검증 자료

최소 묶음은 **확보 가능한 Mosel 모형 + 문제 규모 정의 + 당시 결과 자료의 보유 여부**입니다.

- [ ] Xpress Mosel 원본 또는 공개 가능한 발췌. 변수·목적함수·단위·가중치·대표 제약식. 대응 자료: E008.
- [ ] 소규모 2문제·대규모 2문제별 승객·차량·노드 수와 입력 구조. 대응 자료: E009.
- [ ] 당시 목적함수 값, 비교 오차 기준, 실행 시간, Solver 종료 상태·최적성 갭, 시간창 검사 자료 중 실제 남아 있는 항목. 대응 자료: E012, E013.
- [ ] 원본 Python 코드와 로그가 다른 백업에 남아 있는지. 없다면 미보유 상태를 유지합니다.
- [ ] 실제 ALNS 제거·삽입 연산자, 선택·가중치 갱신 정책, 해 수용·종료 조건을 확인할 당시 자료.
- [ ] 실제 2-opt 적용 방식과 승하차 선후관계·차량 용량·시간창 재검사 방법.

당시 자료를 찾지 못해 새로 재구현한다면 **재구현 날짜·코드·입력·결과**를 별도 기록해 주세요. 새 결과를 당시 실험 결과로 대체하지 않습니다. 기억으로 확인하는 내용은 본인 확인 경험으로 구분합니다.

### 4순위 — P004 RentalTrack의 당시 경험과 재구성 범위

최소 묶음은 **당시 자료 1개 + 당시 작성 범위와 현재 재구성 범위의 구분**입니다.

- [ ] 당시 서비스 흐름도·ERD·요구사항·API 명세·회의 기록 중 공개 가능한 자료. 대응 자료: E023~E027.
- [ ] 본인이 당시 직접 작성·수정한 부분, 팀 공동 작업, 이후 포트폴리오용으로 정리한 부분.
- [ ] Member 연결, 각 관계의 카디널리티·필수 여부, 계약별 인수·반납·검수 기록 수와 중복 제한.
- [ ] 사진 누락·검수 재작성·상태 정정 때의 정책. 실제 구현 정책과 현재 설계 제안을 구분해 주세요.
- [ ] 실제로 충돌했던 요구사항, 우선순위에 따라 제외한 기능, 합의 전후 문서나 논의 기록.

계약 A/B/C와 손상 변화는 현재 가상 예시로 유지합니다. 실제 계약·손상·고객 기록으로 표현하지 않습니다.

## 공통으로 확인할 사항

- [ ] 공개 가능한 자료의 범위. 비공개 자료는 필요한 부분만 가림 처리한 발췌로 제공할 수 있습니다.
- [ ] 개인 기여는 담당 모듈·작성 산출물·팀 공동 작업으로 설명해 주세요. 현재 저장된 기여율의 산정 기준이 없다면 공개 수치로 추가하지 않습니다.
- [ ] 실제로 비교한 대안, 선택 이유, 감수한 비용, 검증 방법. 검토하지 않은 대안을 사후에 경험처럼 만들지 않습니다.
- [ ] 지원 직무나 채용 공고가 정해졌다면 해당 내용. 프로젝트 순서와 강조점을 맞추는 데 사용하며 현재 직무·경력 사실을 임의로 변경하지 않습니다.

자료를 받기 전에는 성능 개선율·정확도·테스트 통과·운영 성공·최적성·미확인 키와 제약을 추가하지 않습니다.
