## 상권 DB — 제공 DAMX 기준 (2026-11-09)

- 49개 테이블 / 621개 컬럼: SRC 21개·367컬럼, DIM 10개·98컬럼, FACT 18개·156컬럼. 원본의 영문 물리 테이블명·컬럼명·타입·PK 인덱스 및 한글 논리명을 추출합니다.

- NULL 허용 여부·관계 차수·추가 UNIQUE는 해독하지 않았습니다. NULL은 상세에서 ‘미확인’으로 표시하며, DAMX 관계에는 다중성 끝표시를 임의로 붙이지 않습니다.
- 상권·매출·점포 8개 테이블을 기본으로, 인구·소득·소비 / 시설·아파트 / 브랜드·점포·매출 / 본부·공시·비용 / 원천 SRC / 분석 DIM·FACT / 전체 49개를 선택합니다. 각 보기는 처음부터 모든 컬럼을 표시합니다.

- 공개 파일은 행 데이터 없는 모델 메타데이터 `public/models/commercial-district.damx.json`입니다. DAMX 원본 바이너리는 새로 공개하지 않습니다. 앱 데이터는 이 추출본과 정확히 일치하도록 생성하고 해시로 검증합니다.

## ERD 표시 방식 · 2026-11-08

- DA# 원본 화면 제어가 불가능하여 사용자가 허용한 프론트 재현 방식을 적용합니다. 원본 캡처로 설명하지 않습니다.
- 사각 엔터티·키 구분선·직각 관계선·다중 관계 끝표시로 표현합니다. 전체 구조 화면은 모든 PK·FK·일반 컬럼을 처음부터 표시하며 개수 제한과 컬럼 접기 기능을 두지 않습니다. 키 영역과 일반 속성을 구분선으로 나누고 일반 속성은 불필요한 빈 키 칸 없이 전체 너비를 사용합니다. 타입·NULL·고유 제약은 상세 모드와 선택 테이블 영역에서 읽습니다. 보조 글씨는 14px 이상을 유지합니다.
- 상권은 제공 DAMX의 상권·매출·점포 8개, RentalTrack은 제공 DAMX와 같은 13개 업무 테이블을 먼저 보여줍니다. 인증·기존 이력 이전 확장은 별도 영역에 유지합니다. 상권은 위 DAMX 추출 기준, RentalTrack은 검증한 SQL을 사용하며, DAMX에서 해독하지 못한 제약을 추정하지 않습니다.
- RentalTrack 업무 모델은 넓은 화면에서 컬럼 수를 고려해 5개 열에 분산합니다. 태블릿에서는 3열, 작은 화면에서는 2열·1열로 재배치하며 테이블·컬럼을 잘라 숨기거나 글자를 축소하지 않습니다. 화면 크기가 바뀌면 엔터티 크기와 관계선 경로를 다시 계산합니다. 상권의 28개·49개 전체 모델은 최소 도표 너비를 유지하고 내부에서 좌우 이동하며, 영역별 보기는 모바일 1열까지 재배치합니다.
- 관계선은 FK 컬럼 행에서 시작하여 해당 원본 모델 또는 SQL의 참조 PK·키 컬럼 행으로 연결합니다. 복합 FK는 컬럼 대응 순서대로 선을 나누며, 같은 PK를 여러 FK가 참조할 때는 해당 PK 행 안에서 연결점을 분리합니다. 전체 구조는 실제 DOM 행 좌표, 상세 모드는 컬럼별 SVG 행 좌표를 사용하며 모바일 줄바꿈·확대 배율에도 맞춥니다.
- 엔터티와 연결점 근처의 진입 구간을 피해 직각 경로를 탐색하여 선분을 공유하지 않으며, 교차점은 배경색 여백으로 구분합니다. FK 쪽에 관계 끝표시를, 참조 키 쪽에 화살표를 표시합니다. 선택 테이블의 연결은 강조하고 해당 관계만 필터링할 수 있으며 선에 마우스를 올리면 컬럼 쌍을 확인합니다.
- 웹 프로젝트 순서는 `sortOrder`를 기준으로 상권→RentalTrack→AI 리포트→승객 수요 경로 최적화입니다. 목록은 세로 4행·1열이며 상세 번호와 다음 프로젝트 이동도 이 순서를 따릅니다.

## 유지보수·검증

`node scripts/build-project-visuals.mjs`는 상권 DAMX 추출 JSON과 나머지 공개 저장소 체크아웃의 고정 커밋을 읽고 SHA-256을 대조한 뒤 구조를 생성합니다. `--check`는 저장된 구조와 다시 비교합니다. 소스 체크아웃은 사이트 빌드에 필요하지 않습니다.

SQL 추출 계약은 `npm run check:visuals`, 저장된 테이블·키·관계·뷰와 처리 분기는 `npm run validate:data`, 각 진입 화면은 `npm run check:render`로 검사합니다. 배포 워크플로에서도 추출 계약을 실행합니다. SQL 기반 ERD의 숫자는 테이블 사이의 참조 범위이며, FK의 NULL 허용과 자식 키의 UNIQUE 여부에서 도출합니다. DAMX에서는 미해독 관계 차수를 표시하지 않습니다. 부모에 자식 행이 반드시 있다고 추정하지 않습니다.

관계명은 카드·다른 선·다른 관계명과 충돌하지 않는 선분에 배치하며, 공간이 부족하면 선의 툴팁과 선택 테이블의 연결 관계 목록에서 확인합니다. 키 행의 연결점을 격자 반올림으로 합치지 않고 각각의 실제 좌표를 보존합니다.
