# 프로젝트 시각 자료

적용일: 2026-11-08. 콘텐츠는 `portfolio_codex_bundle/portfolio-data.json`의 프로젝트별 `visualization`에 둡니다. 기존 25개 개인 수행 작업·9개 지표·담당 범위는 변경하지 않습니다. 공개 화면에서는 설계 구조와 처리 동작을 설명하며, 아래의 추출·검토 기록을 본문에 옮기지 않습니다.

## 상권 DB

- 기준: `Franchise_Recommendation_DB` 커밋 `944b28f6715ace4289ae85d7498910f021046998`의 `sql/schema.sql`.
- 7개 테이블, 컬럼 58개, FK 6개를 추출합니다. 후속 v2 웨어하우스 테이블은 포함하지 않습니다.
- 점포의 `(서비스_업종_코드, 상권_코드)` 복합 PK와 프랜차이즈 업종의 서비스 업종 참조를 표시합니다. 자치구와 행정동 사이처럼 DDL에 없는 관계는 그리지 않습니다.
- ERD의 테이블·컬럼은 영문 snake_case로 표시합니다. 실제 테이블명·컬럼명·키·FK 식별자는 한글 SQL 이름으로 보존하고 `displayName`으로 표현만 바꿉니다. 상세의 접힌 SQL 이름 대응표에서 두 이름을 연결합니다. 선택 목록과 상세 제목은 같은 이름을 반복하지 않으며, 연결 관계에도 영문 테이블명을 사용합니다.

## RentalTrack

- 기준: `RentalTrack` 커밋 `3c1adca8bfd18fd5737617123c8644b3fc73d6ee`의 V11·V12 마이그레이션.
- 업무·공통 코드 13개, 인증 1개, 이전 운영 확장 3개의 테이블을 영역별로 보여줍니다. 이전 버전에서 보존한 레거시 테이블은 이 업무 모델의 전체 보기에 포함하지 않습니다.
- PK·복합 UNIQUE·FK·NULL 허용을 SQL에서 추출하고, V12의 `member_credential.password_hash` NULL 허용 변경을 적용합니다.
- 검수의 `contract_id` UNIQUE, 인수·반납 기록의 별도 FK, 기존·반납 손상의 별도 FK를 구분합니다. 실제 FK가 없는 상태 코드·동적 대상 ID에 임의 연결선을 붙이지 않습니다.
- `image_analysis_result`는 분석 후보를 보관하는 스키마로 표시합니다. 이미지 분석 모델의 구현·실행 성과를 새로 주장하지 않습니다.

## ERD 표시 방식 · 2026-11-08

- DA# 원본 화면 제어가 불가능하여 사용자가 허용한 프론트 재현 방식을 적용합니다. 원본 캡처로 설명하지 않습니다.
- 사각 엔터티·키 구분선·직각 관계선·다중 관계 끝표시로 표현합니다. 전체 구조 화면은 모든 PK·FK·일반 컬럼을 처음부터 표시하며 개수 제한과 컬럼 접기 기능을 두지 않습니다. 키 영역과 일반 속성을 구분선으로 나누고 일반 속성은 불필요한 빈 키 칸 없이 전체 너비를 사용합니다. 타입·NULL·고유 제약은 상세 모드와 선택 테이블 영역에서 읽습니다. 보조 글씨는 14px 이상을 유지합니다.
- 상권은 7개 테이블, RentalTrack은 제공 DAMX와 같은 13개 업무 테이블을 먼저 보여줍니다. 인증·기존 이력 이전 확장은 별도 영역에 유지합니다. 스키마 구조·FK·복합키의 기준은 기존에 검증한 SQL이며, DAMX에서 해독하지 못한 제약을 새로 추정하지 않습니다.
- RentalTrack 업무 모델은 넓은 화면에서 컬럼 수를 고려해 5개 열에 분산합니다. 태블릿에서는 3열, 작은 화면에서는 2열·1열로 재배치하며 테이블·컬럼을 잘라 숨기거나 글자를 축소하지 않습니다. 화면 크기가 바뀌면 엔터티 크기와 관계선 경로를 다시 계산합니다.
- 관계선은 실제 FK 컬럼 행에서 시작하여 SQL이 지정한 참조 PK·키 컬럼 행으로 연결합니다. 복합 FK는 컬럼 대응 순서대로 선을 나누며, 같은 PK를 여러 FK가 참조할 때는 해당 PK 행 안에서 연결점을 분리합니다. 전체 구조는 실제 DOM 행 좌표, 상세 모드는 컬럼별 SVG 행 좌표를 사용하며 모바일 줄바꿈·확대 배율에도 맞춥니다.
- 엔터티와 연결점 근처의 진입 구간을 피해 직각 경로를 탐색하여 선분을 공유하지 않으며, 교차점은 배경색 여백으로 구분합니다. FK 쪽에 관계 끝표시를, 참조 키 쪽에 화살표를 표시합니다. 선택 테이블의 연결은 강조하고 해당 관계만 필터링할 수 있으며 선에 마우스를 올리면 컬럼 쌍을 확인합니다.
- 웹 프로젝트 순서는 `sortOrder`를 기준으로 상권→RentalTrack→AI 리포트→승객 수요 경로 최적화입니다. 목록은 세로 4행·1열이며 상세 번호와 다음 프로젝트 이동도 이 순서를 따릅니다.

## 유지보수·검증

`node scripts/build-project-visuals.mjs`는 로컬의 기존 공개 저장소 체크아웃에서 고정 커밋을 읽고 SHA-256을 대조한 뒤 스키마 구조를 생성합니다. `--check`는 저장된 구조와 다시 비교합니다. 소스 체크아웃은 사이트 빌드에 필요하지 않습니다.

SQL 추출 계약은 `npm run check:visuals`, 저장된 테이블·키·관계·뷰와 처리 분기는 `npm run validate:data`, 각 진입 화면은 `npm run check:render`로 검사합니다. 배포 워크플로에서도 추출 계약을 실행합니다. ERD의 숫자는 테이블 사이의 참조 범위이며, FK의 NULL 허용과 자식 키의 UNIQUE 여부에서 도출합니다. 부모에 자식 행이 반드시 있다고 추정하지 않습니다.
